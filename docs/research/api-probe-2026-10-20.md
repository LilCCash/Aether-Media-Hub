# Fatti verificati dalle fonti primarie (API probe del 2026-10-20)

Il sandbox di sviluppo non raggiunge i siti dei servizi, quindi il workflow manuale `API probe` (`.github/workflows/api-probe.yml`) li legge da un runner GitHub
senza alcuna credenziale (le chiamate autenticate usano volutamente una chiave non valida per osservare la forma degli errori). Questo file riporta **solo ciò che
il probe ha effettivamente restituito**; ciò che non è qui resta "non verificato".

## TorBox (`https://api.torbox.app/v1/api`)

* Specifica OpenAPI pubblica scaricata; percorsi presenti, tra gli altri: `/user/me`, `/torrents/checkcached` (metodi **GET e POST**), `/torrents/createtorrent`
  (**multipart/form-data**), `/torrents/mylist`, `/torrents/requestdl`, `/torrents/controltorrent`, `/torrents/torrentinfo`, `/torrents/asynccreatetorrent`,
  `/user/auth/device/start` e `/user/auth/device/token` (flusso "device code": esiste ma **non è stato verificato né adottato**: Aether usa la chiave API).
* `checkcached`: parametri query `hash` (array), `format` (default `object`), `list_files` (bool, default false); il POST accetta un corpo JSON con la lista di hash.
* `mylist`: query `id`, `bypass_cache`, `offset` (0), `limit` (1000).
* `requestdl`: query `token` (**obbligatorio**, è la chiave API), `torrent_id` (int, obbligatorio), `file_id` (int, default 0), `zip_link`, `user_ip`, `redirect`, `append_name`.
* `user/me`: `settings` (bool). Descrizione ufficiale: "Requires API key".
* Errori osservati con chiave non valida:
  * `GET /user/me`, `checkcached`, `requestdl` → **HTTP 403** `{"success":false,"error":"AUTH_ERROR","detail":"An error occurred while verifying your token. Please try again.","data":null}`
  * senza header `Authorization` → **HTTP 401** `{"detail":"Not authenticated"}` (corpo senza `success`/`error`: il client deve gestire anche questa forma).
* Intestazioni di limite osservate (anche su risposte 403): `x-ratelimit-limit: 300`, `x-ratelimit-remaining`, `x-ratelimit-reset` (epoch, decimale), `retry-after: 60`.
  Il server è dietro Cloudflare.
* Condizioni d'uso: la pagina `https://torbox.app/terms` è una pagina renderizzata lato client (2,5 KB, senza testo utile): **le condizioni non sono state lette**.
  Per questo Aether non automatizza nulla oltre a ciò che l'utente chiede (nessuna cancellazione/riparazione automatica, nessuna chiave condivisa, chiave solo dell'utente).

## TMDB (`https://api.themoviedb.org/3`)

* La specifica OpenAPI (3 MB) dichiara lo schema di sicurezza `Authorization: Bearer` (token di lettura API v4). La chiave v3 in query (`api_key=`) risponde ancora:
  con chiave non valida → **HTTP 401** `{"status_code":7,"status_message":"Invalid API key: You must be granted a valid key.","success":false}`.
* `GET /3/find/{external_id}` con `external_source` ∈ `imdb_id, facebook_id, instagram_id, tvdb_id, tiktok_id, twitter_id, wikidata_id, youtube_id`.
* `GET /3/movie/{movie_id}`, `/3/tv/{series_id}`, `/3/tv/{series_id}/season/{season_number}` con `language` (default `en-US`) e `append_to_response`.
* `GET /3/search/multi` (`query`, `include_adult`, `language`, `page`).
* Termini d'uso (testo letto): l'uso **commerciale** è vietato senza accordo scritto; Aether è gratuito e open source, la chiave è dell'utente, ed è obbligatoria
  l'attribuzione ("This product uses the TMDB API but is not endorsed or certified by TMDB") con il logo: mostrata nelle impostazioni.

## TheTVDB v4 (`https://api4.thetvdb.com/v4`)

* `POST /v4/login` con JSON `{"apikey": "...", "pin": "..."}` (il `pin` è facoltativo e serve per le chiavi "user-supported"); risposta `data.token`, "valido un mese".
* Chiave non valida → **HTTP 401** `{"status":"failure","message":"InvalidAPIKey: apikey invalid","data":null}`.
* I percorsi `/series/{id}/extended` ecc. non sono stati trovati con la ricerca testuale usata dal probe (la specifica usa un'altra forma): **da non dare per scontati**.
* La pagina delle informazioni API è stata scaricata ma il filtro del probe non ne ha estratto il testo sull'attribuzione: **termini non verificati**.

## OpenSubtitles v3 (addon Stremio, nessuna chiave)

* `https://opensubtitles-v3.strem.io/manifest.json`: `id org.stremio.opensubtitlesv3`, `resources ["subtitles"]`, `types ["movie","series"]`, `idPrefixes ["tt"]`, nessun catalogo.
* `GET /subtitles/movie/tt0111161.json` → `{"subtitles":[…]}` con voci del tipo
  `{"id":"30949","url":"https://subs5.strem.io/en/download/subencoding-stremio-utf8/src-api/file/36919","SubEncoding":"CP1252","lang":"eng","m":"i","g":"11",
  "subtitleFileName":"…srt","movieReleaseName":"…","releaseGroup":"aFLDp","releaseFormat":"HDTV","fpsMilli":23980,"season":0,"episode":0}`.
  La lingua è **ISO 639-2** a tre lettere (osservate: `eng, ell, pob, por, spa, slv, tur, fre, ron, cze, hrv, heb, nor, dan, fin, rus, swe`; `pob` = portoghese brasiliano).
* Serie: `GET /subtitles/series/tt0944947:1:1.json` → 94 voci con `season`/`episode`.
* Con `…/tt0111161/videoHash=8e245d9679d31e12&videoSize=12909756.json` il server accetta gli extra e risponde (stesso elenco di 39 per un hash arbitrario:
  **il comportamento con un hash realmente corrispondente non è stato osservato**).
* Il file si scarica da `…/subencoding-stremio-utf8/…` con `Content-Type: application/x-subrip; charset=utf-8`: il server **ricodifica già in UTF-8**; la rilevazione
  della codifica serve per gli altri addon. `SubEncoding` indica la codifica originale.
* L'API REST ufficiale (`https://api.opensubtitles.com/api/v1/infos/languages`) risponde alla lista lingue anche con `Api-Key` non valida (endpoint pubblico);
  le ricerche e i download richiedono una chiave per applicazione e un token utente: **non adottata** in Alpha 2 (termini non letti).

## Cinemeta (addon di cataloghi ufficiale)

* `manifest.json` v3.0.14: `resources ["catalog","meta","addon_catalog"]`, `types ["movie","series"]`, `idPrefixes ["tt"]`.
* Cataloghi: `top` ("Popular", extra `genre` (19 opzioni film / 22 serie), `search`, `skip`), `year` ("New", `genre` **obbligatorio** con 107/67 anni come opzioni, `skip`),
  `imdbRating` ("Featured", `genre`, `skip`), `last-videos` e `calendar-videos` (extra obbligatori `lastVideosIds`/`calendarVideosIds`: **non sono cataloghi sfogliabili**).
* `meta/series/tt0944947.json` espone `imdb_id`, `moviedb_id` (**TMDB id**), `tvdb_id`, `genres`, `logo`, `background`, 128 `videos` (ognuno con `tvdb_id`, `season`, `episode`).
* `catalog/movie/top/search=matrix.json` e `catalog/movie/top/genre=Action.json` funzionano; **`search` e `genre` insieme non sono dichiarati come combinabili**:
  il manifest elenca gli extra separatamente, quindi non si può assumere che il server li combini (vedi `SearchPlan`).
* Nei risultati dei cataloghi `genres` può essere `null` (ricerca) e `year` `null` con `releaseInfo` valorizzato: i filtri locali devono conteggiare gli elementi senza dato.

## MPVKit (motore libmpv per iOS)

* Licenza del repository: **LGPL-3.0** (prodotto `MPVKit`); il prodotto `MPVKit-GPL` è soggetto a GPL-3.0 (include samba). Aether userebbe solo il prodotto LGPL.
* Release: `1.1.0-n9.0.2` (pre-release), `1.0.0` (stabile), `0.41.0-n8.1.2`/`0.41.0-n8.1` (pre-release), `0.41.0` (stabile); 36 asset ciascuna.
* `Package.swift`: `swift-tools-version:5.9`, `iOS(.v15)`; binari XCFramework scaricati da GitHub Releases (Libmpv, Libavcodec/format/…, Libplacebo, **Libdovi**,
  MoltenVK, Libshaderc, Libass, Libdav1d, gnutls, …).
* **Il README del progetto dichiara**: «MPVKit is only suitable for learning libmpv and will not be maintained too frequently. For production use, consider
  AetherEngine (https://github.com/superuser404notfound/AetherEngine)». Metal è supportato solo da una patch non ufficiale di mpv (#7857).
* Il repository include un'app demo iOS con `MPVMetalViewController` e `MetalLayer.swift` (implementazione di riferimento di `vo=gpu-next` su CAMetalLayer).
